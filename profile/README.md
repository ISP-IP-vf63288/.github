<h2>这一篇讲的是「一条线路怎么配进路由器」，不是双线路负载</h2>
<p>双 ISP 这个说法容易让人以为一定要配两条线路。其实大多数使用场景是：服务商给你一条线路（它的地址属性是双 ISP），你要把它正确地配进自己的路由器，让后面的设备能稳定出网。</p>
<p>所以下面讲的是单线路接入的完整设置，重点是「配得对、验得准」，而不是负载均衡。</p>

<h2>第一步：确认物理接入与拨号方式</h2>
<p>先确认这条线路是「插上就能用」还是「需要拨号」。前者由服务商侧完成认证，路由器只要设成自动获取地址；后者需要在路由器里填账号密码。</p>
<p>这一步搞错，后面全白做。表现是路由器拿不到地址，或者拿到了但出不去。问清服务商这一句，能省掉大量试错。</p>

<h2>第二步：WAN 侧参数</h2>
<p>WAN 口要设的有：接入方式（自动获取或拨号）、MTU、以及是否启用 IPv6。MTU 这一项最容易出问题——设得太大，网页能打开但某些服务连不上；设得太小，效率下降。</p>
<p>如果不确定 MTU，先用默认值，出问题再调。判断方法：能打开普通网页但打不开某些应用，通常与 MTU 或分片有关。</p>

<h2>第三步：局域网与地址分配</h2>
<p>局域网网段不要与 WAN 侧冲突。这一点在远程接入场景里尤其重要，如果两边用同一个网段，路由会混乱。</p>
<p>设备地址分配建议用固定绑定，而不是完全动态。把需要长期使用的设备与地址绑定，后续做规则、查日志都方便。完全动态虽然省事，但设备一多就分不清谁是谁。</p>

<h2>第四步：解析设置，别让解析泄露真实位置</h2>
<p>这一项最容易被忽略，但影响很大。如果路由器的解析服务器填的是本地运营商的，那所有查询都会先跑到本地再回来，外部看到的解析来源与出口地区不一致。</p>
<p>正确做法是让解析跟着出口走。可以在路由器上指定解析服务器，或让解析请求经出口转发。配好之后一定要验证，方法是用检测工具看解析来源与出口是否一致。</p>

<h2>第五步：设备接入与权限</h2>
<p>接入层要做的三件事：给每台设备明确的身份（固定地址或独立凭据）、限制管理界面的访问来源、关闭不用的功能（比如远程管理、通用即插即用）。</p>
<p>第三项经常被忽略。这些便利功能在开放环境下会变成入口，关掉不影响正常使用，但能减少很多风险。</p>

<h2>配好之后怎么验证</h2>
<p>四项验证：一，设备能正常上网。二，出口地址与预期一致。三，解析来源与出口一致。四，多台设备同时使用时互不干扰。</p>
<p>第二项和第三项要分别测。出口对了不代表解析也对，很多人只测第一项就以为配好了。</p>

<h2>五个常见排错场景</h2>
<p>一是能连上但打不开网页：先查解析，再查 MTU。二是部分应用连不上：多半是 MTU 或端口问题。三是速度明显低于标称：查是否被限速、是否有人占用带宽。</p>
<p>四是隔一段时间就断：查路由器的会话数上限、查是否过热、查线路本身是否抖动。五是换了设备就不通：查是否做了地址绑定或访问限制。</p>
<p>五个场景的共同点是「先分层再定位」。一上来就重置路由器，往往把现场信息也清掉了，反而更难查。</p>

<h2>常见问答</h2>
<h3>需要专门的路由器吗？</h3>
<p><strong>答：</strong>单线路接入用普通路由器就行。需要做双线路或复杂分流时才需要支持双 WAN 的设备。</p>
<h3>路由器要开 IPv6 吗？</h3>
<p><strong>答：</strong>看服务商是否提供。开了可能影响部分场景的一致性，不确定时先关。</p>
<h3>解析必须改吗？</h3>
<p><strong>答：</strong>如果业务对地区一致性有要求，建议改。普通使用影响不大。</p>
<h3>多台设备会不会互相影响？</h3>
<p><strong>答：</strong>会共享带宽。建议在路由器上做限速，避免单台跑满。</p>
